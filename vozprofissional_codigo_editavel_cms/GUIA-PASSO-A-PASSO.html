NETLIFY + GITHUB + PAGES CMS

Publicação sem sustos.
Atualização sem código.

O site está pronto para publicação em ambiente de testes. Depois de conectar GitHub, Netlify e Pages CMS, você mesmo poderá acrescentar vídeos, áudios, cursos e ebooks pelo navegador.

ETAPA 1 · CONHECER OS DOIS PACOTES

Qual arquivo usar?

01 · Site pronto para testar

Use o ZIP “Publicar agora” para ver a página no Netlify. Descompacte e arraste a pasta para o Netlify Drop. Aqui você vê o site, mas ainda não tem o editor.

02 · Site com painel de edição

Use o ZIP “Código editável”. Coloque no GitHub, conecte o Netlify e configure o Pages CMS. Esse é o caminho definitivo para troca fácil das mídias.

ETAPA 2 · PRÉVIA SEM RISCO

Publique a prévia no Netlify

  1. Entre em app.netlify.com/drop.
  2. Descompacte vozprofissional_publicar_agora.zip no computador.
  3. Arraste a pasta descompactada (com index.html na raiz) para a área de publicação.
  4. O Netlify fornecerá um endereço provisório nomedosite.netlify.app. Acesse e teste os vídeos, os filtros, os botões e o celular.
Importante: não altere o DNS do Wix nessa etapa. O site principal continuará onde está.
ETAPA 3 · ATUALIZAÇÕES FÁCEIS

Coloque o código no GitHub

  1. Crie uma conta em github.com, se ainda não tiver.
  2. Instale o GitHub Desktop no computador.
  3. Descompacte vozprofissional_codigo_editavel.zip. No GitHub Desktop, escolha File → Add local repository, selecione essa pasta e, se solicitado, clique em Create a repository here.
  4. Clique em Publish repository. Recomendo deixá-lo como Private.

Não é necessário editar o HTML nem o JavaScript para adicionar novos trabalhos depois da configuração.

ETAPA 4 · PUBLICAÇÃO AUTOMÁTICA

Conecte o Netlify ao GitHub

  1. No Netlify, selecione Add new project → Import an existing project → GitHub.
  2. Autorize o repositório Voz Profissional e selecione a branch main.
  3. O arquivo netlify.toml define os parâmetros: node scripts/build.mjs e publicação da pasta dist.
  4. Depois do primeiro deploy, acesse a URL gerada e teste a página. Faça futuras publicações pelo editor, não por um ZIP manual.

Se você tiver publicado antes pelo Netlify Drop, poderá usar um novo projeto importado do GitHub; não precisa alterar o site Wix.

ETAPA 5 · PAINEL DE CONTROLE

Ative seu editor visual

  1. Acesse app.pagescms.org e clique em entrar com GitHub.
  2. Instale/autorize o aplicativo Pages CMS apenas para o repositório criado.
  3. Abra o repositório. O arquivo .pages.yml apresentará duas áreas: Portfólio — vídeos e áudios e Treinamentos e ebooks.
  4. Para trocar um vídeo, abra o trabalho, edite o campo “Link do YouTube” e salve.
  5. Para adicionar uma amostra de áudio, clique em criar novo item, selecione “Áudio”, escolha “Audiolivros” (ou outra categoria), envie um MP3 curto e marque “Mostrar no site”.
  6. Para reordenar ou ocultar, use “Ordem” e “Mostrar no site”. Cada salvamento aciona uma nova publicação automática no Netlify.
Arquivos de áudio: use amostras em MP3 ou M4A leves. Para arquivos grandes, prefira um link HTTPS para armazenamento externo. Para vídeos, use YouTube; o GitHub não é um serviço de hospedagem de vídeos longos.
ETAPA 6 · WIX E DOMÍNIO

Preserve as páginas que já vendem

Inicialmente o Netlify funcionará num endereço de teste, e www.vozprofissional.com continuará no Wix. O DNS dirige domínios e subdomínios a uma hospedagem; não mantém automaticamente algumas pastas no Wix e outras no Netlify.

Antes de apontar o domínio principal para o Netlify, migre ou preserve URLs de campanhas (por exemplo, /ebook), páginas de treinamento e páginas indexadas. O site atual depende dessas URLs e de integrações do Wix.

Opção mais segura no começo

Conecte somente um subdomínio como portfolio.vozprofissional.com ao Netlify, mantendo o domínio principal no Wix.

Opção para o lançamento final

Depois da revisão de URLs e integrações, conecte o domínio principal ao Netlify pelos registros DNS exatos indicados no painel do Netlify.

Antes do lançamento público: altere SITE_MODE = "staging" para "production" no arquivo netlify.toml. O modo de teste impede indexação da página em buscadores.

CONFERÊNCIA FINAL

Checklist antes de mostrar aos clientes

  1. Testar reel e exemplos do YouTube; conferir se todos permitem incorporação.
  2. Testar a reprodução das amostras de áudio no celular.
  3. Conferir e-mail, WhatsApp, Instagram e YouTube.
  4. Validar links de cursos, ebooks, preços e páginas de compra.
  5. Se houver migração do domínio principal, revisar páginas antigas, redirecionamentos, integrações de marketing, e-mail e DNS.
